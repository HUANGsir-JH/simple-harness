# Web UI 设计记录（feat/webui，2026-08-16）

> 权威实施计划已写入当前会话 plan 文件（v3，两轮 review 修订）；本文档是
> 分支内的静态设计记录，供后续维护参考。版本 0.14.0。

## 背景与目标

`harness web` 启动本地 HTTP 服务，浏览器承载 TUI 全部功能（消息流/工具块/
审批/提问/斜杠命令/队列/中断/唤醒/子 agent/plan/todo/用量），体验更友好
（点击交互、多窗口、富渲染）。前端风格：简洁、直观、易用。

## 关键决策

| 决策点 | 结论 | 理由 |
|---|---|---|
| 分支 | `feat/webui`（从 main 拉出） | 任务要求独立分支开发测试 |
| 后端框架 | gin v1.10.1 | 用户指定；v1.12 要求 go 1.25，锁定 v1.10.x 保持 go 1.24.2 |
| 前端 | 零依赖 HTML/CSS/JS + go:embed | 无 node 构建链，单二进制 |
| 事件推送 | SSE（EventSource） | 单向推送足够，标准库/gin 原生支持 |
| markdown | 后端 goldmark+chroma 渲染 HTML 片段 | events.Event 不能加字段 → SSE 包装层附加 html |
| 命令路由 | POST /api/input 统一入口，select 在 HTTP 响应返回选项 | 命令逻辑全收敛后端，前端无状态 |
| 审批/提问 | SSE 广播 + request_id 回填；无订阅者自释放 | 页面全关防回合卡死 |
| 多标签页 | 全局共享 active 会话 + state_changed 全量同步 | 对位 TUI 单客户端语义（一个终端一个会话） |
| 安全 | POST Origin/Sec-Fetch-Site 校验；默认 127.0.0.1 | 防 DNS rebinding 驱动本机 agent |

## 架构

```
internal/app/             # ModeWeb + buildWeb + runWeb + signals（SIGINT+SIGTERM）
internal/web/             # ★ web 模式运行时（对位 internal/ui/tui）
  server.go               # gin 路由（/api/* 先注册 + /static StaticFS）+ SSE + 三阶段生命周期
  hub.go                  # SSE 订阅者集合 + 广播（锁内快照锁外发送，缓冲 64 满则丢）
  controller.go           # WebController：会话注册表 + 输入路由 + run 编排（并发契约）
  approver.go             # webApprover：request_id pending 表 + 回填 + ctx 释放
  command.go              # 斜杠命令分发（对位 tui/command.go + popup.go）

```

## WebController 并发契约（review 核心产出）

TUI 依赖 bubbletea 单线程主循环天然串行；web 多 handler/goroutine 必须显式
加锁。以下字段读写全在 `c.mu` 内：`running / queue / cancel / interrupted /
approvals / asks / seq / active / open / viewSubID / toolCalls`。

- **队列消费防双 run**：run 收尾在**同一锁临界区**内完成 `running=false →
取 queue 下一条 → running=true + setCancel`，再启动 goroutine（对齐
MaybeWake 同步抢占警告：绝不在 goroutine 内才置位）。
- **switch/new running 拒绝**：独立端点不入队（防事件落盘错会话 + 并发写）。
- **中断**：`Interrupt()` 置 interrupted + cancelRun + 清空 approvals/asks 表
  （孤儿请求防复活）；run 收尾在 tool_result 补全后 AddUser 中断提示（Bug10
  顺序）；wakeNotStarted 不写伪中断。
- **approver**：register 时保存 respCh（Request 持通道 select，不动态查表）；
  决策回填锁内**先删表再发通道**（缓冲 1，第二个响应 404）；ctx.Done 释放 +
  defer delete。
- **onEvent**：锁内取 active 快照 → Hub 广播（带 session_id + 附加字段）+
  `sess.OnAgentEvent` 落盘；工具事件经 `toolEvent` 缓存/分派（tool_call 预读
  write_file 旧文件）。
- **收尾顺序**：Hub.Close（断 SSE）→ Shutdown（带超时）→ WaitRuns →
  SaveActiveState → CloseAll → Teardown（subagents.Shutdown）。

## API 摘要

- `GET /api/state`：sessions + active（状态栏）+ timeline（msg-<序号>/
  tool-<call_id>）+ running + queue_len + pending（重连恢复审批/提问）。
- `GET /api/events`（SSE）：`agent`（ev + html/summary/tool/err_text）/
  `approval`/`ask`（request_id）/`run_done`（error/interrupted/queue_len）/
  `state_changed`（switch|new|rename|compact|subagent_view|subagent_exit|status）/
  `system`。所有事件带 session_id（前端按 active 过滤）。
- `POST /api/input`：消息 → started；running 时一切输入入队 → queued；
  命令 → ok/select/compact_started/exit/help；错误 → !ok。
- `POST /api/interrupt|approve|ask|new|switch`。

## 前端要点

- **单一 stream 块**：⚠ `thinking_delta`/`text_delta`/`turn_start`/`turn_done`
  **无 MsgID**——严禁按 msg_id 关联；delta 追加到当前 stream（rAF 合并防抖），
  边界 = text_done（换后端 html）/tool_call/turn_done（flush）。
- **reconnecting 标志**：state_changed/onopen 重拉期间丢弃在途增量（防全量/
  增量交错）。
- **overlay 互斥 + pendingOverlays FIFO**：select/approval/ask/help 统一排队
  （对位 TUI Bug10/缺陷03）。
- **安全渲染**：流式期 textContent；块完成后 innerHTML 只用后端 goldmark
  输出（goldmark 默认丢弃原始 HTML）+ tool 输出转义。
- **四态矩阵**：空态（无会话引导）/加载态/错误态（系统行+toast）/断线态
  （顶栏横幅 + EventSource 自动重连 onopen 重拉）。

## 实施前 review 摘要

两个 explore 子 agent 审查计划 v2 后输出缺陷清单（后端 17 项 + 前端 27 项），
高严重度代表：

- H1 switch/new running 无守卫 → 事件落盘错会话 + data race（→ running 拒绝）
- H2 队列消费 running 置位竞态（→ 锁内串行消费）
- H3 approvals/asks pending 表清理缺失（→ defer delete + 中断/切换清空）
- H4 interrupted/wakeNotStarted 标志缺失（→ 补字段与语义）
- H5 SSE 长连接卡死 Shutdown（→ Hub.Close 先断 + 带超时）
- H6 ModeWeb 无 SIGINT 监听（→ signals 分支）
- S1 SSE 事件无会话归属（→ 全部事件带 session_id）
- S2 delta 无 MsgID（→ 单一 stream 块）
- S3 多标签页单例 active 冲突（→ 全局共享 + state_changed 同步）
- S4 tool_call/tool_result 缺分派数据（→ SSE 包装层附加 summary/tool）
- S5 events.Event.Err 无法序列化（→ err_text 字段）
- S6 页面关闭审批挂起（→ 无订阅者自释放）
- M11 无 CSRF 防护（→ Origin/Sec-Fetch-Site 校验）

全部缺陷已整合进计划 v3 并落地实现与测试。
